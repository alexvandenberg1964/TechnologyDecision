🔵 Low-Code
▼
Cost model: Capacity & Platform-oriented

Costs are influenced by runtime resources, database capacity, storage, environments, HA/fallback, scaling, and enterprise licensing agreements.

What drives cost?
  • Application runtime capacity
  • Database size and capacity
  • File storage
  • Number of environments (dev, test, acceptance, production)
  • High availability and fallback requirements
  • Horizontal scaling and headroom for peaks
  • Enterprise licensing and internal chargeback model
Caveat: Low-Code can still be the better total-cost choice when fast delivery, business involvement, process fit, and available capability significantly reduce build and change costs.
🟢 High-Code (reference: )
▼
Cost model: Usage-based

You pay across the services the architecture consumes — compute, queues, event routing, databases, storage, observability, networking, and security services.

What drives cost?
  • Compute duration and request volume
  • Queue, event, and message volume
  • Database reads, writes, storage, and provisioned capacity
  • API calls, load balancing, and data transfer
  • Logs, metrics, traces, alarms, and retention
  • Networking, NAT, security, KMS, secrets, and WAF
  • High availability and disaster recovery setup
Caveat: is not automatically cheap. Poor architecture, overlogging, inefficient database access, NAT Gateway misuse, excessive data transfer, or overprovisioning can make it materially more expensive. 🟣 Hybrid
▼
Cost model: Dual — boundary separates the models

Hybrid separates the UI/process cost model from the event/backend cost model. A clean architecture boundary lets each layer use the cost model that matches its workload shape, instead of forcing one model across the full solution.

Low-Code layer
Capacity-based
Runtime · DB · Envs
HA · Scaling · Licence
High-code layer
Usage-based
Compute · Queues · Events
Logs · API · Networking
Requirements for cost model separation to work
  • A clear, defined, and owned architectural boundary
  • Separate team ownership per layer
  • Both cost models budgeted and governed independently
Note: Both caveats apply — Low-Code is not always more expensive, and High-Code cloud cost (reference: ) is not automatically cheaper. Evaluate each layer independently.
